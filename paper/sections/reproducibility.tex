\section{Experimental Protocol}
\label{sec:reproducibility}
Source code and reproduction instructions are available at
\url{https://github.com/yet-another-ai/jet}.
The \href{https://github.com/yet-another-ai/jet#build}{installation instructions}
and \href{https://github.com/yet-another-ai/jet/blob/main/tests/accuracy/README.md}{evaluation guide}
cover setup, pinned data and model preparation, and benchmark execution.

The RTX 4090 campaign uses the mean-token decision rule throughout, with
reasoning disabled. All thirteen full-set runs and eighteen backend controls
are complete. Its recorded UTC run date range is \jetresult{suite}{date},
its executable hash prefix is \texttt{\jetresult{suite}{binary}}, and its
source revision prefix is \texttt{\jetresult{suite}{source}}.
Per-run provenance retains full hashes, the working-tree patch, model identity,
runtime flags, and environment overrides. Measurements from earlier scoring
implementations are not imported.

\subsection{Full-MMLU Runs}
All full runs use the 14,042 MMLU test questions across 57 subjects. Data
preparation verifies the pinned archive checksum. Inputs can be regenerated
with \texttt{prepare-accuracy-data.py --boolq-limit 0 --mmlu-all --ascii-json}.
Windows CRLF and Linux LF serialization have different byte hashes; the
question records and their order must agree. The evaluator treats identical
answer texts under distinct option labels as equivalent.

Six pretrained models are evaluated with both CUDA and Vulkan on the RTX 4090:
Qwen3.5-0.8B, 2B, 4B, and 9B use Q8\_0; Qwen3.5-27B and
Qwen3.6-35B-A3B use Q4\_K\_M. The thirteenth full run evaluates the
LoRA-adapted Qwen3.5-4B Q8\_0 with CUDA. The text benchmark loads no visual
projector. All runs use full GPU placement, eight CPU threads, two sequence
slots, a microbatch size of 256, an output-row limit of 256, eight requests per
chunk, and no memory mapping.

Each configuration has one fresh-process run without explicit warm-up or cache
eviction. A result is admitted only after successful process completion,
14,042 responses, zero evaluation failures, and matching input, gold, executable,
and protocol provenance. Timings include startup, loading, JSONL processing,
and shutdown. Responses, logs, timings, and subject-level reports are retained
locally outside version control. Generated aggregate evidence and the figure
data identify the completed runs used by the manuscript. Full-MMLU accuracy
and throughput for a configuration always come from the same run.

\subsection{Adapted Model Provenance}
The completed LoRA training and export are retained under \texttt{training/}.
The pinned HF checkpoint, source checksums, data split manifest, optimizer
configuration, adapter, and export identity are preserved. Only inference is
rerun for this scoring revision; the adapter and weights are unchanged.
The CUDA reference and adapted evaluations use the same input and gold,
executable, batch size, and JET flags. Paired correctness includes semantic
equivalence when option labels share answer text.

The adapted model is a merged text-only Q8\_0 GGUF made with
\texttt{--no-nextn}; the pre-existing reference GGUF includes MTP weights and
comes from a separate conversion repository. A zero-adapter export of the
pinned training checkpoint has not been evaluated, so this comparison does
not isolate adaptation from source and conversion provenance.

\subsection{GPU Backend Sensitivity}
\label{sec:backend-sensitivity}
The control suite contains 570 questions: for each subject, take the ten
smallest SHA-256 hashes of the gold-record identifier and then restore the
original full-set ordering. This selection does not use model responses.
All controls use the same executable, model files, inputs, and full-run flags.
Environment overrides select each Vulkan path.

The suite has eighteen fresh-process runs. Qwen3.5-0.8B has ten: CPU, CUDA,
Vulkan default, a repeat of each GPU default, and five Vulkan variants.
Qwen3.5-2B and Qwen3.6-35B-A3B each have four: CUDA, Vulkan default,
Vulkan without \texttt{NV\_coopmat2}, and Vulkan without either cooperative-matrix
path. For 0.8B, the five Vulkan variants disable \texttt{NV\_coopmat2};
both cooperative-matrix paths; both paths plus FP16; both paths plus integer
dot product; or all four features. Thus the FP16 and integer-dot-product
comparisons are conditional on cooperative-matrix paths already being disabled.
Logs record the backend, actual execution features, and full layer placement.

\subsection{Pending Arc A770 and Prefix Studies}
The Arc A770 follow-up targets an i9-13900K, 64\,GiB RAM, and a 16\,GiB GPU.
Four full-MMLU runs will use Qwen3.5-0.8B, 2B, 4B, and 9B Q8\_0 with Vulkan
and the same mean-token scoring and runtime flags as the RTX 4090 campaign.
Their results and figure points remain pending until complete runs are available.

The shared-prefix follow-up uses 256 label-balanced BoolQ validation examples
and five MMLU test examples from each of 57 subjects, totaling 541 requests
(seed 20260921). Both independent execution and prefix reuse must apply the
current mean-token rule. The intended comparison keeps eight requests per
chunk, nine sequence slots, 2,048 context tokens per sequence, token batches
of 2,048, a microbatch size of 512, and an output-row limit of 256. One
independent-execution run and two prefix-reuse runs per model permit a limited
timing comparison, with model order reversed for the second round. Speedup,
prefix-token work, exact-response equivalence, and state-isolation diagnostics
require fresh measurements; no previous numerical result is carried forward.

\subsection{External Reference Boundaries}
Jev 1.13's manually measured 89.06\% full-MMLU accuracy and 2.86 requests/s API
rate lack documented concurrency and detailed timing boundaries. Its interface
exposes no configurable reasoning or few-shot settings. These author-supplied
values remain external context. Published larger-model results retain their
source protocols. Neither shared benchmark coverage nor normalization of JET's
decision weights establishes calibrated confidence or matched-system equivalence.
