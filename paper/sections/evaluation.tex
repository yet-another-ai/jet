\section{Experimental Evaluation}
\label{sec:evaluation}
\subsection{Experimental Setup}
We evaluate decision quality, local deployment cost, and execution efficiency
using MMLU and BoolQ decision tasks~\cite{boolq,mmlu}. Full-MMLU evaluations compare JET and Jev; sampled evaluation sets support
model-selection and execution-optimization experiments.
The principal comparisons disable reasoning generation; optional thinking is
examined separately. Dataset construction, runtime settings, and reproduction
commands are provided in Appendix~\ref{sec:reproducibility}.

Accuracy is measured by agreement with the reference answer: choice predictions
use the highest-probability label, and BoolQ thresholds the true probability at 0.5. Gold negative
log-likelihood (NLL) is computed from the normalized candidate distribution.
The custom zero-shot prompt and semantic scoring protocol differ from standard
leaderboard procedures. The results therefore characterize the evaluated JET
configurations rather than official benchmark scores for the underlying models.

Complete-process wall time includes initialization, model loading, evaluation,
and shutdown. Reported throughput is the number of requests divided by this
elapsed time. It is distinct from saturated serving throughput; similarly,
amortized time per request is distinct from a latency percentile. Fresh processes
may reuse operating-system and shader caches. Run counts and configuration
changes are reported for each comparison. Accuracy and NLL characterize the
scoring method; execution-time comparisons identify the optimizations enabled
in each configuration.

\subsection{Local Deployment on Consumer Systems}
\label{sec:local-deployment}
The evaluated configurations span CPU-only inference, a desktop CPU with a
16\,GiB consumer GPU, and full placement on an RTX 4090. These configurations
establish a practical deployment range without server-class accelerators.
The Qwen3-0.6B CPU baseline completes 541 decisions in approximately 220 seconds
(2.46 requests/s), while its Arc A770 configuration completes the same workload
in 69.51 seconds (7.78 requests/s). The smaller model's limited accuracy, reported
below, distinguishes basic deployment feasibility from suitability for demanding
decision tasks.

The larger Qwen3.6-35B-A3B model demonstrates how local resource allocation can
support higher decision quality. On an RTX 4090 with full GPU placement, it
achieves 87.48\% accuracy on full MMLU with a throughput of 3.69 requests/s. On a desktop
with an i9-13900K, 64\,GiB RAM, and a 16\,GiB Arc A770, expert offloading enables
execution despite model weights exceeding device memory. The latter configuration
achieves 87.37\% on its 285-question MMLU subset at an amortized cost of 1.109
seconds per request over the mixed workload. These are separate experiments,
not a controlled hardware comparison. Together they demonstrate that high-quality
local decisions are feasible within the measured consumer configurations, with
latency determined by model size, placement, and execution efficiency.

\subsection{Decision Quality and Model Selection}
The initial Qwen3-0.6B Q8\_0 CPU comparison replaced a canonical-JSON prompt with
opaque output labels by a human-readable Tera prompt and semantic candidate
answers. On the same inputs, BoolQ improved from 128/256 (50.00\%) to 143/256
(55.86\%), and MMLU from 63/285 (22.11\%) to 109/285 (38.25\%). The old MMLU
configuration chose label A on 283 of 285 examples. Because both rendering and
answer representation changed, this is a combined prompt-contract comparison,
not an isolated ablation of semantic scoring.

Table~\ref{tab:models} reports disabled-thinking decision quality on the same
541 requests using Vulkan on the Arc A770. The small models use Q8\_0 weights
and full GPU placement; Qwen3.6 uses Q4\_K\_M with CPU expert offloading.
The scoring formulation is unchanged by the prefix, worker-pool, and preparation
optimizations. Response-equivalence checks in Sections~\ref{sec:prefix-results}
and~\ref{sec:repeatability} support retaining these accuracy results across the
corresponding execution changes. Runtime effects are evaluated separately.

The 2B model improves combined accuracy over the smaller models, and the 35B MoE

\paragraph{Functional and performance comparison with Jev.}
Both systems expose sampler-free decision interfaces over caller-specified
alternatives. Sampler-free selection is therefore a shared property rather than
a distinction between JET and Jev. JET contributes a way to obtain this behavior
from reusable pretrained models with local execution. Both expose boolean probabilities, named choices, and rubric scores. JET
computes its score as the expectation of zero-based level indices and returns
candidate probability maps for choice and score questions. Jev additionally
reports separate confidence values for those question types; JET's normalized
likelihoods are not presented as equivalent calibrated confidence estimates. Jev describes
parallel evaluation of independent questions; JET's hybrid path evaluates
candidate continuations serially while sharing their prefix~\cite{jev-docs,jev-workflows}.

The manual Jev 1.13 measurement reports 2.86 requests/s via API. JET reaches
3.69 requests/s locally on the RTX 4090, including process startup and model
loading. These observations establish local deployment at a comparable reported
request rate, but differing workloads and timing boundaries preclude a controlled
speedup claim. Figure~\ref{fig:mmlu-throughput} consolidates the measured quality
and throughput results. Published larger-model reference scores remain in
Table~\ref{tab:mmlu-comparison}, since corresponding throughput measurements
are unavailable. JET exposes local placement, model choice, and optional thinking;
the evaluated Jev interface does not expose a thinking mode. No Jev hardware
configuration is inferred from its API throughput.

\subsection{Numerical Equivalence and Reproducibility}
\label{sec:repeatability}
The prefix, threadpool, and preparation comparisons demonstrate exact response
agreement within their tested configurations. These comparisons support numerical equivalence for the evaluated transformations
and environments. Cross-platform invariance does not follow from these observations. In the recorded
Qwen3-0.6B CPU/Vulkan comparison, 14 of 541 top-1 predictions change and the
maximum absolute candidate-probability difference is 0.2998.

Independent reference execution tests the preservation of candidate-state
semantics. An earlier hybrid sibling-fork schedule changed 9 of 20 diagnostic
answers relative to independent candidate execution. The corrected schedule
matches top-1 decisions on that diagnostic slice, with maximum probability
difference $1.12\times10^{-7}$. A later independent-request batching experiment
also exceeded the unchanged numerical tolerance and was not retained. Current
hybrid results use the serial continuation schedule described above.

\subsection{Optional Thinking: Accuracy--Throughput Trade-off}
\label{sec:thinking-results}
JET can optionally generate a reasoning trace before evaluating candidates,
allowing applications to spend additional computation to improve decision quality.
This provides an explicit accuracy--throughput trade-off without changing model
weights or the typed decision interface. The benefit is task-dependent: on the
Qwen3-0.6B workload, enabling thinking reduces throughput from 7.78 to 0.84
requests/s while raising BoolQ accuracy from 55.47\% to 65.23\% and combined
accuracy from 47.13\% to 50.46\%. MMLU accuracy instead decreases from 39.65\%
to 37.19\%. Thus, optional thinking expands the available operating modes, but
its use should be guided by validation on the target task. Candidate evaluation
remains sampler-free conditional on the generated trace; the complete reasoning
path includes generation and does not inherit the sampler-free reproducibility
claim.
