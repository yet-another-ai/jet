\section{Experimental Evaluation}
\label{sec:evaluation}
\subsection{Experimental Setup}
We use MMLU and BoolQ~\cite{boolq,mmlu} to examine three questions: what
decision quality pretrained models provide, whether they can support local
inference on consumer hardware, and how execution optimizations affect cost
at fixed decision quality. Full-MMLU evaluations compare JET and Jev; fixed
subsets support model comparisons and execution studies. The principal
comparisons disable reasoning generation; optional reasoning is examined
separately. Appendix~\ref{sec:reproducibility} describes the data and settings.

Accuracy is measured by agreement with the reference answer: choice predictions
use the highest-probability label, and BoolQ thresholds the true probability at 0.5. Gold negative
log-likelihood (NLL) is computed from the normalized candidate distribution.
The zero-shot prompt and semantic scoring protocol differ from standard
leaderboard procedures; the results characterize the evaluated JET configurations.

Complete-process wall time includes initialization, model loading, evaluation,
and shutdown. Reported throughput is the number of requests divided by this
elapsed time. It is distinct from saturated serving throughput; similarly,
amortized time per request is distinct from a latency percentile. Fresh processes
may reuse operating-system and shader caches. Run counts and configuration
changes are reported for each comparison.

\subsection{Local Deployment on Consumer Systems}
\label{sec:local-deployment}
The evaluated configurations span CPU-only inference, a desktop CPU with a
16\,GiB consumer GPU, and full placement on an RTX 4090. These configurations
establish a practical deployment range without server-class accelerators.
The Qwen3-0.6B CPU baseline completes 541 decisions in approximately 220 seconds
(2.46 requests/s), while its Arc A770 configuration completes the same workload
in 69.51 seconds (7.78 requests/s). The smaller model's limited accuracy, reported
below, distinguishes basic deployment feasibility from suitability for demanding
decision tasks.

Qwen3.6-35B-A3B achieves 87.48\% accuracy on full MMLU with full GPU placement
on an RTX 4090. A separate 285-question experiment with this configuration
reaches 3.69 requests/s; this is not a timing measurement of the full-MMLU run.
On an i9-13900K with 64\,GiB RAM and a 16\,GiB Arc A770, CPU expert offloading
allows execution despite weights exceeding GPU memory. This configuration
achieves 87.37\% on its 285-question MMLU subset, with an amortized cost of
1.109 seconds per request over the mixed workload. These separate experiments
show that high-quality local decisions are feasible on the measured consumer
systems, but they do not form a controlled hardware comparison.

\subsection{Decision Quality and Model Selection}
A Qwen3-0.6B Q8\_0 CPU comparison replaced a structured prompt with opaque
output labels by a readable prompt and semantic candidate answers. On the same
inputs, BoolQ improved from 128/256 (50.00\%) to 143/256 (55.86\%), and MMLU
from 63/285 (22.11\%) to 109/285 (38.25\%). The old MMLU configuration chose
label A on 283 of 285 examples. Both prompt presentation and answer
representation changed, so this comparison does not isolate semantic scoring.

Table~\ref{tab:models} reports disabled-thinking decision quality on the same

\paragraph{Functional and performance comparison with Jev.}
Both systems provide sampler-free decisions over supplied alternatives,
including boolean probabilities, named choices, and rubric scores. JET obtains
this behavior from reusable pretrained models with local execution. JET
computes its score as the expectation of zero-based level indices and returns
candidate probability maps for choice and score questions. Jev additionally
reports separate confidence values for those question types; JET's normalized
likelihoods are not presented as equivalent calibrated confidence estimates. Jev describes
parallel evaluation of independent questions; JET's hybrid path evaluates
candidate continuations serially while sharing their prefix~\cite{jev-docs,jev-workflows}.

The manual Jev 1.13 measurement reports 2.86 requests/s via API. JET reaches
3.69 requests/s locally on the RTX 4090 on the 285-question subset, including
startup and model loading. The reported rates show that local execution can
support a similar request rate, but differences in workloads and timing
boundaries preclude a controlled speedup claim. JET exposes local placement,
model choice, and optional reasoning; the evaluated Jev interface does not
expose a reasoning mode. Its hardware configuration is unknown.

Figure~\ref{fig:mmlu-throughput} summarizes the best-performing evaluated
JET configuration for each model and hardware deployment, with reasoning
disabled, alongside Jev. Early prompt baselines, intermediate optimization
variants, and repeated measurements are omitted from the figure. Model choice changes decision quality; the prefix,
worker, and preparation comparisons improve throughput without changing
responses. Within JET, the largest evaluated model provides the highest MMLU
accuracy, while smaller models can offer higher throughput. Optional reasoning
does not improve MMLU accuracy in the measured small-model experiment. These
results distinguish gains from model capability and execution efficiency,
with task-dependent benefits from extra reasoning.

The figure combines distinct experiments: CPU and Arc A770 throughput covers
mixed BoolQ/MMLU workloads, whereas RTX 4090 throughput covers MMLU alone.
For the full-MMLU row, 87.48\% accuracy is measured on the complete test set,
but the plotted 3.693 requests/s is taken from the separate 285-question run
of the same configuration. It is not the measured throughput of the full-set
run. Jev uses the full-MMLU accuracy and separately reported API rate.
Published larger-model scores remain in Table~\ref{tab:mmlu-comparison}
because corresponding throughput measurements are unavailable.

\subsection{Numerical Equivalence and Reproducibility}
\label{sec:repeatability}
The prefix, CPU-worker, and preparation comparisons preserve exact responses
in their tested configurations. This does not imply agreement across platforms. In the recorded
Qwen3-0.6B CPU/Vulkan comparison, 14 of 541 top-1 predictions change and the
maximum absolute candidate-probability difference is 0.2998.

Independent candidate execution provides a reference for testing state
isolation. An initial hybrid schedule changed 9 of 20 diagnostic answers.
Restoring independent candidate states recovered agreement on all top-1
decisions in that slice, with a maximum probability difference of
$1.12\times10^{-7}$. A separate experiment batching independent requests
exceeded the same numerical tolerance and was not retained. These checks
support the use of serial candidate continuations in the reported hybrid
experiments.

\subsection{Optional Thinking: Accuracy--Throughput Trade-off}
\label{sec:thinking-results}
Optional reasoning generates a trace before candidate evaluation, exchanging
computation for a possible improvement in quality without changing model
weights. The benefit is task-dependent: on the
Qwen3-0.6B workload, enabling thinking reduces throughput from 7.78 to 0.84
requests/s while raising BoolQ accuracy from 55.47\% to 65.23\% and combined
accuracy from 47.13\% to 50.46\%. MMLU accuracy instead decreases from 39.65\%
to 37.19\%. Optional reasoning therefore requires validation on the target task. Candidate evaluation
remains sampler-free conditional on the generated trace; the complete reasoning
path includes generation and does not inherit the sampler-free reproducibility
claim.
